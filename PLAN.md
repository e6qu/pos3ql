# pos3ql roadmap

Architecture: [README.md](README.md). Naming: [docs/terminology.md](docs/terminology.md). Working rules: [AGENTS.md](AGENTS.md). Unresolved blockers only: [BUGS.md](BUGS.md).

## Architecture objectives

- PostgreSQL compatibility is SQL text, v3 wire bytes, catalog behavior, and logical replication where it suits the object-native design; PostgreSQL heap pages, physical XLOG, and binary-WAL replication are not targets.
- Object storage is the only durable tier. RAM and local disk are bounded, disposable caches.
- The engine uses one generic object-store gateway contract; provider protocols and SDKs remain outside the application.
- Acknowledgement must have an object-native latency and request shape: immutable commit batches plus CAS publication, not one remote upload per transaction.
- Runtime memory is fixed at startup. Pool exhaustion is a loud error.
- Unsupported PostgreSQL semantics fail explicitly; no fallback or accept-and-ignore path exists.

## Completion work

1. **Object-native durability.** Complete: readable protocol batches publish immutable commit data and a CAS commit head before acknowledgement; checkpoints retain their replay boundary, clear only manifest-captured table generations, and retry post-publication cleanup until completion.
2. **Object-store portability.** Complete: application configuration and transport use only the generic gateway contract; the deterministic simulator and integration gateway qualify that contract. No application provider adapter or provider-specific branch is permitted.
3. **SQL and catalogs.** Close remaining language, type, privilege, collation, and introspection differences through strict PostgreSQL differential tests. Collation identity is typed from syntax through column metadata, catalog projection, WAL, and checkpoints; comparison rejects incompatible identities. A startup-owned locale runtime serves scalar predicates, aggregates, materialized and spill sorting, joins, indexes, uniqueness probes, foreign-key actions, grouping, windows, and set operations. Index keys are typed columns or expressions, with `INCLUDE`, partial predicates, and `NULLS NOT DISTINCT` retained across transactions, WAL, checkpoints, catalogs, uniqueness checks, and conflict arbitration. Global, tablespace, and concurrent variants remain explicit gaps. Aggregate window `FILTER` is supported; PostgreSQL rejects `DISTINCT` and argument ordering in a window call.
4. **Wire and binary protocol.** Match PostgreSQL Bind, Result, COPY, cancellation, array/range/composite, and typmod bytes for every accepted type. One catalog-aware parameter resolver serves text and binary Bind plus nested records, including domains, enums, arrays, and unknown text; binary cursors retain binary result framing through FETCH; malformed structured values fail as a whole.
5. **Logical replication.** Keep pgoutput, slot, and subscription work only where it preserves object-native performance; physical/binary-WAL replication remains deliberately unsupported.
6. **Physical-demand execution.** Complete: every base-source path carries an opaque selected-column proof or an explicit full-row reason through joins, correlation, CTEs, materialization, sorting/grouping/window spill, set operations, and DML/`MERGE` sources.

## Delivery order

One large PR is open at a time; it is merged and `main` is refreshed before the next begins.

1. **Arrays and composites.** Complete: one rectangular shape preserves dimensions and lower bounds through SQL, storage, text/binary Bind, Result, portals, COPY, WAL, checkpoints, recovery, catalogs, and PostgreSQL cross-load for every modeled built-in, catalog, enum, domain, range, multirange, and composite element type. Named composites keep stable type/backing-relation identities through schema/name moves and attribute add, rename, drop, type, and nullability changes. Historical values render against the current layout; domain chains rebind their ultimate named base after recovery. Attribute renames atomically rewrite typed domain checks, table defaults/generated columns/checks, nested and set-operation views, and expression-index predicates/keys, including same-transaction reads, while unrelated identifiers, literals, comments, and SQL function bodies remain unchanged. `DROP TYPE` follows typed table, composite-field, and stored-query dependencies under `RESTRICT`/`CASCADE`; pg_dump/restore, raw-wire, driver, crash-restart, and object-store cold-start tests cover the boundary.
2. **SQL semantics.** In progress: generated PostgreSQL-valid SQL has no unsupported budget; differential comparison preserves decoded value types and total result order. Array construction, aggregation, subqueries, bounds, and extended-protocol results share one rectangular-shape model. Record fields retain names and types through derived and set-operation sources, row descriptions, ordinal ordering, and grouping. Row-valued quantified subqueries have a distinct typed AST and retain arity, output types, collations, NULL truth tables, and bounded object-run probes. Multi-argument `unnest`, multidimensional `generate_subscripts`, catalog record SRFs, `ROWS FROM`, `WITH ORDINALITY`, nested built-in and SQL-routine project sets, record expansion, LATERAL and joined sources, CTEs, recursive queries, set operations, views, DML sources, binary portals, dump/restore, and cold recovery share PostgreSQL's project-set levels and lockstep/NULL-padding rule. Stored queries bind routine overload OIDs durably, follow routine identity changes, and enforce PostgreSQL dependency drops. Continue closing semantic differences through strict differential tests.
3. **DDL and catalogs.** In progress: typed column, domain, enum, sequence, schema, view, routine, index, trigger, and partition definitions are transaction-owned state across DDL, WAL, recovery, checkpoints, and catalog visibility. Declarative range, list, hash, and default partition metadata uses resolved key offsets, typed bound values, and parent slots; routing has one storage choke point. Parent scans, streamed COPY, and writable `UPDATE`, `DELETE`, `UPDATE … FROM`, and matched `MERGE` retain each leaf’s physical row identity, including partition-key movement and cold recovery. Parent `BEFORE INSERT` triggers run before routing, while direct-leaf writes revalidate their bound afterward. Parent publication membership includes routed leaves with PostgreSQL’s default leaf identity and filtering. `pg_class`, `pg_inherits`, and `pg_partitioned_table`, PostgreSQL differential, psycopg extended-protocol, and raw-wire coverage exercise catalog identity, range, list, hash, default, parent reads/writes, `RETURNING`, and cross-leaf updates. Cross-partition constraints, durable trigger inheritance, partition attach/detach, pruning, subpartitioning, and `publish_via_partition_root` remain. Triggers retain PostgreSQL `ORIGIN`, `REPLICA`, `ALWAYS`, and `DISABLED` modes through named, `ALL`, and `USER` `ALTER TABLE` targets, including views. Routine signatures and return contracts retain built-in, enum, domain, composite, and array identities rather than executor slots; overload resolution, `pg_proc`, dump/restore, Bind/Result, WAL, and checkpoints use that same contract. Routine replacement preserves its OID, ownership, ACLs, and dependent triggers.
4. **Wire and bulk data.** In progress: typed text/binary Bind, nested records, scalar subqueries, derived sources, set operations, and materialized CTEs share catalog resolution and retain typmods. A spooled scalar subquery preserves its runtime datum; its catalog witness describes empty results without coercing aggregate values. Correlation analysis resolves against the statement catalog snapshot. Explicit catalog casts remain typed through anonymous record fields, common-type expressions, nullable `CASE` branches, array constructors/fill/aggregates, polymorphic array functions, subscripts, slices, `unnest`, and value window functions. Whole-row expansion preserves each declared type modifier and collation. `regtype`, `regclass`, `regrole`, `regnamespace`, `regproc`, `regprocedure`, `regoper`, and `regoperator`, including their arrays, retain OID-backed states through declarations, defaults, rows, WAL, checkpoints, Bind, casts, `pg_typeof`, materialization, and Result; stored catalog references resolve their current names after rename. Operator aliases resolve the evaluator-supported PostgreSQL 18.4 catalog identities and reject all others explicitly. Malformed Bind bytes report binary-input errors rather than COPY-file errors. COPY FROM owns its parsed `WHERE` predicate and typed format/error controls across streamed text and binary input; predicates run after coercion/defaults and before constraints, count only stored rows, and reject subqueries or generated columns before CopyInResponse. Malformed rows and non-conversion failures remain strict. Binary COPY query output accepts every catalog-resolved type with a binary send form, including domains, enum/domain arrays, and records. The PostgreSQL-oracle matrix covers built-in values with unambiguous text input through Bind, Result, named portals, and bidirectional binary COPY, including bounded numeric, temporal, interval, bit, and array modifiers; raw-wire probes cover catalog-resolved values, malformed framing, non-default array bounds, and binary portal paging. Close remaining accepted-type typmod, portal, and driver behavior.
5. **Replication.** In progress: publication definitions, including column lists and row filters, and subscription connection/publication definitions are typed, transaction-owned catalog values across SQL, WAL, recovery, checkpoints, catalog reads, pgoutput, and apply. Subscription row application has an explicit replication origin, so only `REPLICA` and `ALWAYS` row triggers fire through the ordinary bounded trigger executor; pgoutput apply deliberately has no statement-trigger boundary, matching PostgreSQL. A stream capability binds slot, creation stamp, and committed definition generation; it alone can advance the acknowledgement frontier, so an ALTER invalidates queued old-stream commits before they can become durable. Workers reconnect on that capability while ordinary frontier movement keeps the session. pgoutput v1–v4, raw frames, real PostgreSQL publishers, TLS, crash recovery, and slot acknowledgement cover the boundary. Enabled subscriptions require a named, pre-existing publisher slot and reject remote slot creation and initial copy explicitly. Snapshot export is rejected explicitly.

## Current invariants

- Catalog identity, DDL visibility, domain, enum, named-composite, and sequence definitions, and retained TZif cache entries are atomic typed states.
- Client OID identities cross catalog functions through one checked parse boundary; wide values cannot wrap into another object.
- A composite attribute has one stable physical number; its `Composite(slot)` type tag is the referenced-composite identity. A dropped attribute remains a typed physical hole; stored values are decoded by physical number and new client values by active logical position, so neither a rename nor add/drop evolution can create a stale field mapping or dependency lookup by name.
- Composite WAL records carry durable catalog slots for definitions and their typed fields. Recovery alters exact identities rather than allocating coincidentally free slots; stored-query type dependencies likewise carry an explicit composite class.
- A named enum or composite has one slot/OID across schema and name changes. The shared type namespace is reserved by its committed or transaction-pending identity; every durable reference moves in the same catalog commit.
- A domain base is either a built-in type, a parent-domain identity, or a typed direct enum/composite identity; checkpoint loading rebinds that identity only after the complete catalog exists, before it is exposed.
- Direct and domain composite arrays retain their distinct array element OID and the composite physical layout. Binary Bind/COPY input validates both; Result/COPY output writes the matching element OID and binary records; subscripting retains the named-composite shape for field resolution.
- A collation is either absent or a resolved identity; it cannot be accepted and discarded. Columns, derived relations, CTEs, set operations, indexes, WAL, checkpoints, catalogs, and comparison compatibility retain that identity.
- Persisted default tags and bounded payloads are parsed as typed states; malformed lengths and type codes are rejected rather than reinterpreted.
- Binary arrays and records resolve catalog domain identities before accepting NULLs, so a domain `NOT NULL` or CHECK cannot be bypassed inside a Bind value or binary COPY field.
- COPY FROM options and `WHERE` source become a connection-owned bounded setup before the statement arena is reset. `ON_ERROR ignore` can discard only data-conversion errors; malformed framing, constraints, and durable-write failures cannot be misclassified as ignorable rows. A successful row is typed as stored or filtered, so command counts cannot include filtered candidates.
- Accepted built-in array OIDs resolve through one inventory for binary input, catalog projection, and Result descriptions; a newly modeled array cannot disappear at one boundary.
- A sequence's staged parameters and value state are visible only to the owning transaction; rollback restores the exact savepoint image and WAL publishes only the final committed image.
- Every engine error and dynamic trigger code carries a validated five-character SQLSTATE value; arbitrary text cannot reach a handler, stacked diagnostic, or wire response.
- A publisher transaction has matching typed `BEGIN`/`COMMIT` positions; its local row changes and subscription frontier become durable together before a status acknowledgement can leave the worker.
- DML target aliases bind uniformly in predicates, joined sources, static result description, and `RETURNING` evaluation.
- SQL function programs type every formal through CTE, derived, and set-query descriptions. Named formals remain typed candidates until column binding, so a column wins and `function.formal` selects the formal only when no qualified column binds. Every preceding query or DML step runs; the final query or DML `RETURNING` statement supplies the result, and `void` returns typed NULL after its final action. Bounded invocation logs make mutable scalar and table calls exactly-once across projections, predicates, joins, LATERAL scans, nesting, and query materialization. A project-set level materializes each catalog routine once by AST identity; nested levels select their inputs independently before outer lockstep projection. Scalar calls cannot resolve set-returning definitions, and table calls cannot resolve scalar definitions. `RETURNS TABLE` owns ordered result names and types through replacement, WAL, checkpoints, catalogs, and scans.
- A routine has one durable identity and a single transaction-private replacement definition. Its invocation, catalog rendering, dependent triggers, WAL record, checkpoint image, and recovery replay select the same identity; replacement never expresses itself as a drop plus a separately allocated routine.
- A routine argument or result is a runtime representation plus an optional durable user-type identity. Calls resolve on declared OIDs before values can erase a domain to its base representation, so a domain and its base type can be distinct overloads without stale catalog slots masquerading as either.
- A quantified subquery is a typed row set, never an array surrogate. Its declared column types and collations are resolved before execution, including empty and all-NULL sets; inline and object-backed probes apply the same `ANY`/`ALL` truth table.
- Trigger identity uses a typed table-or-view target, timing, events, level, transition-table aliases, enabled state, function link, and bounded invocation arguments. Every firing has one typed `TG_*` context; `OLD`/`NEW` and statement transition tables are typed scopes. Trigger-side SQL recurses through the normal transaction path with an explicit nesting bound.
- A joined trigger DML probe reborrows `OLD`/`NEW` and the decoded target row only for source matching and assignment evaluation; no storage-borrowed datum survives into the mutable write phase.
- Trigger locals have a resolved scalar type and typmod before execution. Declaration initialization, assignment, and `SELECT … INTO` all coerce through that type; ordinary empty `SELECT … INTO` assigns typed NULL, while `STRICT` has typed no-row and multi-row errors. `ASSERT` and `RAISE` form bounded parsed diagnostic nodes: formatting validates placeholder arity before execution, and `USING MESSAGE/DETAIL/HINT` is carried to the client or active handler without stale metadata. Each trigger function has typed execution status: `FOUND` remains nullable and may be shadowed by a local, while `GET [CURRENT] DIAGNOSTICS` receives `ROW_COUNT` from queries and DML without command-tag parsing, `PG_ROUTINE_OID` from the durable routine identity, and a typed routine context frame. `EXCEPTION` conditions, handler-only `SQLSTATE`/`SQLERRM`, and stacked-diagnostic item names are typed parse states; a protected block consumes one bounded internal savepoint and reverses its row, statistics, lock, notification, and subscription effects before the matching handler executes. `GET STACKED DIAGNOSTICS` and bare `RAISE;` are parsed only inside a handler; rethrow preserves the caught SQLSTATE, message, detail, and hint. Trigger-side `INSERT … SELECT` materializes its read result before the write phase, and conflict updates resolve `excluded` against the candidate row while preserving typed trigger locals and `OLD`/`NEW`. Nested joined `UPDATE`/`DELETE` resolve target columns first and locals or transition values only when the target has no matching column.
- Trigger loops target a declared scalar, record, or array local. Numeric bounds and step are evaluated once and use checked `int8` progression; query and array-loop values are detached into the statement arena before the body can write, and sliced arrays preserve trailing dimensions and lower bounds. A loop label resolves to its bounded lexical unwind distance during parsing; `EXIT` and `CONTINUE` cannot escape a loop or perform runtime label lookup. `CASE` selects one typed branch after evaluating its operand once.
- Physical PAX demand is an opaque proof, not a caller-built bitset. Every base scan, hash-join build/probe, unmatched outer-join pass, correlated query, CTE/materialization, set operation, window/group spill, and DML/`MERGE` source scan uses that proof or a named full-row reason. The common expression walker includes function filters/orders/window keys and array access, so a source dependency cannot be omitted by a specialized executor.
- Publication identity, membership, column projections, row filters, schema selectors, operations, and ownership are durable typed states; row-filter source uses one bounded payload per publication rather than reserving space for unused members. Catalog reads see their own staged state, while replication sees only committed selection. A projected update/delete includes its replica identity, and subscriber apply fills omitted inserts from local defaults while preserving omitted update fields.
- A subscription stream is a typed durable capability: catalog slot, creation stamp, and committed definition generation. Its rows and frontier commit together; an ALTER makes every queued prior capability invalid, including during WAL recovery.
- Engine startup initializes named-zone TZif history before allocation freezes; unavailable historical data is not approximated.
- Checksums, immutable blocks, and CAS manifests make cache loss recoverable.
- Cancellation keys are parsed as protocol-versioned values: v3.0 uses four bytes and v3.2 uses the full issued key.
- Network values are constructed only from a valid address family, mask, and canonical address bytes; `cidr` additionally requires host bits clear.
- Verification includes unit/property tests, PostgreSQL differential and SQLLogicTest corpora, driver probes, cold-start/crash recovery, and deterministic fault simulation. Golden `psql` tests compare stdout and stderr separately; CI uses runner `psql` for ordinary SQL, PostgreSQL 18 `psql` for its protocol meta-commands, and PostgreSQL 18 image dump tools, avoiding package-mirror latency.
