# pos3ql roadmap

Architecture: [README.md](README.md). Naming: [docs/terminology.md](docs/terminology.md). Working rules: [AGENTS.md](AGENTS.md). Unresolved blockers only: [BUGS.md](BUGS.md).

## Architecture objectives

- PostgreSQL compatibility is SQL text, v3 wire bytes, catalog behavior, and logical replication where it suits the object-native design; PostgreSQL heap pages, physical XLOG, and binary-WAL replication are not targets.
- Object storage is the only durable tier. RAM and local disk are bounded, disposable caches.
- The engine uses one generic object-store gateway contract; provider protocols and SDKs remain outside the application.
- Acknowledgement must have an object-native latency and request shape: immutable commit batches plus CAS publication, not one remote upload per transaction.
- Runtime memory is fixed at startup. Pool exhaustion is a loud error.
- Unsupported PostgreSQL semantics fail explicitly; no fallback or accept-and-ignore path exists.

## Completion work

1. **Object-native durability.** Complete: readable protocol batches publish immutable commit data and a CAS commit head before acknowledgement; checkpoints retain their replay boundary, clear only manifest-captured table generations, and retry post-publication cleanup until completion.
2. **Object-store portability.** Complete: application configuration and transport use only the generic gateway contract; the deterministic simulator and integration gateway qualify that contract. No application provider adapter or provider-specific branch is permitted.
3. **SQL and catalogs.** Close remaining language, type, privilege, collation, and introspection differences through strict PostgreSQL differential tests. PL/pgSQL scalar, multi-`OUT`, `SETOF`, and `RETURNS TABLE` functions share the bounded procedural executor with procedures, anonymous blocks, and triggers across execution, catalog/WAL/checkpoint recovery, ACLs, security-definer/configuration scopes, and wire calls. Dynamic `EXECUTE` binds command text and `USING` values once, then dispatches typed queries, DML with `RETURNING INTO`, and modeled schema/relation, view, routine, role/ACL, sequence, type, collation, conversion, index, trigger, policy, statistics, full-text, foreign-data, tablespace/database, materialized-view, publication, subscription, reindex, maintenance, and comment utilities without changing `FOUND`. Dynamic DML and utilities share static authorization, command, trigger, WAL, and recovery boundaries. Row-level security, collation identity, indexes, and modeled lifecycle commands retain their typed transactional boundaries.
4. **Wire and binary protocol.** Accepted scalar, geometric, array, domain, enum, range, multirange, and composite types share catalog-aware text/binary Bind, Result, portal, SQL cursor, COPY, and typmod boundaries. Internal `"char"` remains a raw byte through storage, WAL, text/binary output, arrays, records, and COPY rather than becoming UTF-8 text. Continue with types or messages added by later SQL slices; malformed or unsupported states fail as a whole.
5. **Logical replication.** Keep pgoutput, slot, and subscription work only where it preserves object-native performance; physical/binary-WAL replication remains deliberately unsupported.
6. **Physical-demand execution.** Complete: every base-source path carries an opaque selected-column proof or an explicit full-row reason through joins, correlation, CTEs, materialization, sorting/grouping/window spill, set operations, and DML/`MERGE` sources.

## Current invariants

- Catalog identity, DDL visibility, domain, enum, named-composite, and sequence definitions, and retained TZif cache entries are atomic typed states.
- Every database-local catalog object carries one `DatabaseOid`; lookup, ACL rendering, template cloning, WAL replay, checkpoint loading, and synthetic catalogs require that identity before transaction visibility is considered. Shared databases and tablespaces remain explicit object classes rather than database-less local objects.
- A GUC snapshot carries current value, reset value, and one typed precedence source. Cluster reload changes existing sessions only where database, role, client, or session state does not override it; `pg_settings` renders that state instead of inferring provenance from equal strings.
- Client OID identities cross catalog functions through one checked parse boundary; wide values cannot wrap into another object.
- A composite attribute has one stable physical number; its `Composite(slot)` type tag is the referenced-composite identity. A dropped attribute remains a typed physical hole; stored values are decoded by physical number and new client values by active logical position, so neither a rename nor add/drop evolution can create a stale field mapping or dependency lookup by name.
- Composite WAL records carry durable catalog slots for definitions and their typed fields. Recovery alters exact identities rather than allocating coincidentally free slots; stored-query type dependencies likewise carry an explicit composite class.
- A named enum or composite has one slot/OID across schema and name changes. The shared type namespace is reserved by its committed or transaction-pending identity; every durable reference moves in the same catalog commit.
- A domain base is either a built-in type, a parent-domain identity, or a typed direct enum/composite identity; checkpoint loading rebinds that identity only after the complete catalog exists, before it is exposed.
- Direct and domain composite arrays retain their distinct array element OID and the composite physical layout. Binary Bind/COPY input validates both; Result/COPY output writes the matching element OID and binary records; subscripting retains the named-composite shape for field resolution.
- A collation state is absent, resolved with explicit or implicit derivation, or indeterminate; a collatable value cannot be mistaken for a non-collatable value. `UNION ALL` may carry an indeterminate state, while every comparison boundary requires a resolved identity. Columns, records, postponed projections, derived relations, CTEs, set operations, indexes, triggers, WAL, checkpoints, and catalogs retain the state they need.
- A catalog collation is a stable slot plus one validated provider behavior; a conversion owns parsed source and destination encodings and a supported procedure identity. Neither reaches execution as an unchecked spelling.
- An explicit index binds physical columns through the owning table's transaction-visible shape. Dropping a column retires direct, expression, predicate, and covering dependencies before the rewrite; surviving keys and covering columns move through the same typed column map as their table.
- Persisted default tags and bounded payloads are parsed as typed states; malformed lengths and type codes are rejected rather than reinterpreted.
- A role credential and expiry are optional typed values. A membership edge owns its grantor and ADMIN/INHERIT/SET options; a role setting owns one closed role/database scope; object, column, and parameter ACLs have separate typed targets. Default public ACLs become an explicit owner/public image on first mutation, so revoking the final default privilege remains durable rather than reverting after recovery.
- Binary arrays and records resolve catalog domain identities before accepting NULLs, so a domain `NOT NULL` or CHECK cannot be bypassed inside a Bind value or binary COPY field.
- A portal is fresh, paging, or complete. Sync owns implicit-transaction commit and idle portal lifetime; response exhaustion is a named statement error. SQL cursors retain one typed row shape and bounded text/binary representations, so FETCH format selection never re-evaluates a query or reinterprets bytes.
- Routine reference input parses quoted identifiers, nested type modifiers, and top-level signature separators before catalog lookup; commas inside a type modifier cannot become phantom arguments.
- COPY FROM options and `WHERE` source become a connection-owned bounded setup before the statement arena is reset. `ON_ERROR ignore` can discard only data-conversion errors; malformed framing, constraints, and durable-write failures cannot be misclassified as ignorable rows. A successful row is typed as stored or filtered, so command counts cannot include filtered candidates.
- Accepted built-in array OIDs resolve through one inventory for binary input, catalog projection, and Result descriptions; a newly modeled array cannot disappear at one boundary.
- A sequence's staged parameters and value state are visible only to the owning transaction; rollback restores the exact savepoint image and WAL publishes only the final committed image.
- A prepared transaction owns a typed GID, metadata, exact locks, live transaction state, and an immutable recovery record set. Live resolution promotes the original overlays; cold resolution replays only the retained complete batch. The checkpoint manifest pins every unresolved batch until a durable typed resolution releases it.
- A deferred constraint obligation identifies one catalog generation and affected row. Savepoint rollback discards later obligations; renaming preserves identity, while drop/recreate cannot inherit an earlier mode or obligation. Enabling foreign-key enforcement validates existing rows before publishing the state; PostgreSQL 18 rejects changing CHECK enforceability through `ALTER CONSTRAINT`.
- A tablespace cost is a validated finite nonnegative float state. Index placement is a typed provider-neutral tablespace identity; no storage-provider branch or SDK can enter catalog or execution code.
- A cast owns exact source, target, method, context, and support-routine identities. Domain casts remain catalog objects but are ignored during coercion as PostgreSQL specifies. An operator is a shell or a complete typed prefix/binary function contract; overload dependencies retain its OID, so a drop or move cannot silently rebind stored SQL. A btree index binds its resolved operator-class OID at creation and executes the class's validated comparison support function.
- A text-search value is canonical `tsvector` or `tsquery`, never unchecked text. A configuration reference is a stable catalog identity; stored SQL, mappings, WAL, checkpoints, template clones, wire codecs, COPY, and object-cold recovery cannot silently rebind it by spelling.
- An extension dependency is a typed member, automatic, or required edge. A dumpable extension relation is a typed table or sequence with a bounded condition and stable catalog ordinal. Configured package directories and durable object-store packages are explicit startup sources; neither can silently substitute for the other. SQL package bytes and effective version metadata are immutable objects published by the manifest CAS.
- An extended-statistics key is a resolved column identity or an immutable parsed expression. Definitions and ANALYZE data have bounded transaction-private states; column and table evolution rewrites or drops dependencies atomically, and recovery publishes only complete definition/data images.
- A row-security policy has a stable table and role identity, a command-shaped expression state, and bounded dependencies. Permissive predicates OR within a command, restrictive predicates AND, and commands that read target rows conjoin SELECT policy visibility before user expressions run.
- Every engine error and dynamic trigger code carries a validated five-character SQLSTATE value; arbitrary text cannot reach a handler, stacked diagnostic, or wire response.
- A publisher transaction has matching typed `BEGIN`/`COMMIT` positions; its local row changes and subscription frontier become durable together before a status acknowledgement can leave the worker.
- A pgoutput UPDATE identity is either an explicit old image or the new tuple's declared key; streamed child XIDs own bounded local savepoints, so abort cannot erase the parent transaction. Steady-state apply fires PostgreSQL replication-origin row triggers only; initial COPY retains COPY's row-and-statement behavior.
- DML target aliases bind uniformly in predicates, joined sources, static result description, and `RETURNING` evaluation.
- SQL function programs type every formal through CTE, derived, and set-query descriptions. Named formals remain typed candidates until column binding, so a column wins and `function.formal` selects the formal only when no qualified column binds. Every preceding query or DML step runs; the final query or DML `RETURNING` statement supplies the result, and `void` returns typed NULL after its final action. Bounded invocation logs make mutable scalar and table calls exactly-once across projections, predicates, joins, LATERAL scans, nesting, and query materialization. A project-set level materializes each catalog routine once by AST identity; nested levels select their inputs independently before outer lockstep projection. Scalar calls cannot resolve set-returning definitions, and table calls cannot resolve scalar definitions. `RETURNS TABLE` owns ordered result names and types through replacement, WAL, checkpoints, catalogs, and scans.
- A routine has one durable identity and a single transaction-private replacement definition. Its invocation, catalog rendering, dependent triggers, WAL record, checkpoint image, and recovery replay select the same identity; replacement never expresses itself as a drop plus a separately allocated routine.
- A routine argument or result is a runtime representation plus an optional durable user-type identity. Calls resolve on declared OIDs before values can erase a domain to its base representation, so a domain and its base type can be distinct overloads without stale catalog slots masquerading as either.
- A routine parameter owns its mode and optional default. A call retains named and explicit-variadic syntax until overload resolution; ordinary variadic elements are packed once, while an explicit variadic array is never reinterpreted as an element. Procedure output placeholders are not evaluated.
- A routine body is a string, SQL-standard return expression, or SQL-standard atomic block before storage. Its attributes and bounded configuration are part of the same replacement image; invocation restores nested settings and effective authorization without erasing an ordinary `SET` performed by the body.
- A SQL-standard routine body stores its creator path and exact catalog dependencies in a fixed side table. WAL and checkpoints validate that dependency image before publication; execution and the bounded drop closure use the same identities after renames. DML overload binding carries target, joined-source, `excluded`, and `MERGE` column types at creation. A string body never enters that path because PostgreSQL resolves it at invocation.
- A PL/pgSQL program kind is trigger, event trigger, scalar function, void function, output-record function, set function, procedure, or anonymous block. Its typed return form and execution host are fixed before interpretation; only a top-level non-atomic procedure or anonymous block can own a transaction boundary.
- A statement rewind belongs to one transaction identity. A non-atomic routine that reaches a lock or object-read suspension after transaction control fails explicitly instead of replaying a segment that was already committed.
- An aggregate definition owns typed transition, final, combine, serialization, moving, ordering, and polymorphic contracts. Invocation binds pseudo-types once to concrete OIDs; support calls, partial states, RowDescription, catalogs, WAL, checkpoints, and recovery use that same binding.
- Semantic routine and record metadata retains domain identity; PostgreSQL `RowDescription` exposes the domain's base representation. These are separate typed boundaries.
- A quantified subquery is a typed row set, never an array surrogate. Its declared column types and collations are resolved before execution, including empty and all-NULL sets; inline and object-backed probes apply the same `ANY`/`ALL` truth table.
- An interval modifier carries one closed field-range variant and optional validated precision. Parser, coercion, catalogs, wire metadata, COPY, WAL, and recovery cannot invent or reinterpret raw field masks; session interval output selects one typed PostgreSQL style at every scalar or nested text boundary.
- A temporal input model claims exactly one Gregorian, ISO-week, or Julian convention before resolution; mixed conventions cannot reach evaluation. Numeric input models carry positional digits, scaling, signs, and Roman mode in bounded typed tokens.
- A sampled relation carries a closed method, validated percentage and optional seed, inheritance selection, and durable row identity. Sampling decisions are independent of provider blocks and cache residency; every DML source expands stored views before storage becomes mutable.
- A foreign endpoint is a validated PostgreSQL server plus current-role or public mapping and a startup-budgeted transport lease. Catalog credentials are visible only under PostgreSQL's server-owner or mapped-user rules; foreign metadata is one typed database-local dependency graph, and unsupported mutation never enters local row storage.
- A join either has no `USING` clause or one typed merged-column clause with its optional alias. A grouping-set quantifier is `ALL` or `DISTINCT`, and ordering direction is parsed once for query, aggregate, and window lists. Record expansion obtains its declared shape before evaluating NULL, so an outer row or named composite cannot lose columns; Bind inference uses the same resolved expression scope.
- A common table expression carries an explicit default, materialized, or not-materialized state. Recursive search and cycle state is typed, hidden from wildcard expansion, and retained outside the visible row without becoming a durable column type. Query-local scopes preserve outer bindings and shadow them by name. `STABLE` routines remain inline-eligible; `VOLATILE` routines force one bounded effect log, so execution strategy cannot multiply sequence effects.
- Trigger identity is a typed target, timing, event set, level, transition relation, firing mode, routine, and bounded argument list. Partition clones derive stable catalog identity from it while owning transactional firing modes. Constraint-event completion is an append-only undo state until no savepoint can observe it.
- An event-trigger invocation owns its event-derived tag and DDL origin. Only its transaction-local mutations enter its bounded command and dropped-object graphs; nested extension commands retain their own origin and `in_extension` state. Explicit drop roots are typed catalog identities, including routine and operator signatures, rather than name guesses. Only `table_rewrite` can carry a relation OID and reason bitmap.
- A joined trigger DML probe reborrows `OLD`/`NEW` and the decoded target row only for source matching and assignment evaluation; no storage-borrowed datum survives into the mutable write phase.
- Trigger locals have a resolved scalar type and typmod before execution. Declaration initialization, assignment, and `SELECT … INTO` all coerce through that type; ordinary empty `SELECT … INTO` assigns typed NULL, while `STRICT` has typed no-row and multi-row errors. `ASSERT` and `RAISE` form bounded parsed diagnostic nodes: formatting validates placeholder arity before execution, and `USING MESSAGE/DETAIL/HINT` is carried to the client or active handler without stale metadata. Each trigger function has typed execution status: `FOUND` remains nullable and may be shadowed by a local, while `GET [CURRENT] DIAGNOSTICS` receives `ROW_COUNT` from queries and DML without command-tag parsing, `PG_ROUTINE_OID` from the durable routine identity, and a typed routine context frame. `EXCEPTION` conditions, handler-only `SQLSTATE`/`SQLERRM`, and stacked-diagnostic item names are typed parse states; a protected block consumes one bounded internal savepoint and reverses its row, statistics, lock, notification, and subscription effects before the matching handler executes. `GET STACKED DIAGNOSTICS` and bare `RAISE;` are parsed only inside a handler; rethrow preserves the caught SQLSTATE, message, detail, and hint. Trigger-side `INSERT … SELECT` materializes its read result before the write phase, and conflict updates resolve `excluded` against the candidate row while preserving typed trigger locals and `OLD`/`NEW`. Nested joined `UPDATE`/`DELETE` resolve target columns first and locals or transition values only when the target has no matching column.
- Trigger loops target a declared scalar, record, or array local. Numeric bounds and step are evaluated once and use checked `int8` progression; query and array-loop values are detached into the statement arena before the body can write, and sliced arrays preserve trailing dimensions and lower bounds. A loop label resolves to its bounded lexical unwind distance during parsing; `EXIT` and `CONTINUE` cannot escape a loop or perform runtime label lookup. `CASE` selects one typed branch after evaluating its operand once.
- Physical PAX demand is an opaque proof, not a caller-built bitset. Every base scan, hash-join build/probe, unmatched outer-join pass, correlated query, CTE/materialization, set operation, window/group spill, and DML/`MERGE` source scan uses that proof or a named full-row reason. The common expression walker includes function filters/orders/window keys and array access, so a source dependency cannot be omitted by a specialized executor.
- Local ordering and distinctness measure one persistent encoded-row block before filling it; source, catalog, and correlated-subquery scratch is recycled after every input row.
- Publication identity, membership, column projections, row filters, schema selectors, operations, and ownership are durable typed states; row-filter source uses one bounded payload per publication rather than reserving space for unused members. Catalog reads see their own staged state, while replication sees only committed selection. Replica identity is `DEFAULT`, `FULL`, `NOTHING`, or selected-index state across SQL, catalogs, WAL, checkpoints, and pgoutput; update/delete use PostgreSQL's `K` or `O` old-tuple tag only when an identity is usable. Subscriber apply fills omitted inserts from local defaults while preserving omitted update fields.
- A subscription definition is one typed connection, slot, publication, and behavior value. Lifecycle commands read their transaction-visible definition, so a staged slot cannot be confused with its prior stream; rows and frontiers commit only for the matching creation stamp and definition generation, including after WAL recovery.
- A bootstrap snapshot, discovered table set, copied rows, table-ready states, and publisher frontier cross one local commit boundary. Recovery sees either the prior catalog or the complete synchronized state; refresh copies only new relations. Managed publisher slots remain durable cleanup work after the local subscription disappears.
- Engine startup initializes named-zone TZif history before allocation freezes; unavailable historical data is not approximated.
- Checksums, immutable blocks, and CAS manifests make cache loss recoverable.
- Cancellation keys are parsed as protocol-versioned values: v3.0 uses four bytes and v3.2 uses the full issued key.
- Network values are constructed only from a valid address family, mask, and canonical address bytes; `cidr` additionally requires host bits clear.
- Verification includes unit/property tests, PostgreSQL differential and SQLLogicTest corpora, driver probes, cold-start/crash recovery, and deterministic fault simulation. Golden `psql` tests compare stdout and stderr separately; CI uses runner `psql` for ordinary SQL, PostgreSQL 18 `psql` for its protocol meta-commands, and PostgreSQL 18 image dump tools. Forced-spill corpora and independent probes have separate bounded workers.
